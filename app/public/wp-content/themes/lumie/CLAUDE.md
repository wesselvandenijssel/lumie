# Claude Code Repository Instructions

These instructions define the expected standards for all Claude Code completions in this repository. Claude should prefer the examples, syntax, and file structures shown below. Where this file and the global `~/.claude/CLAUDE.md` differ, **this file wins** — it documents how this theme actually works, verified against the code.

## Project Overview

This is MB effect's **base theme**: the template repository that new client sites are forked from. It is a Dutch-language WordPress theme — all editor-facing labels and frontend strings are written in **Dutch**; code, comments, and commit messages are in **English**.

- **Text domain:** `mbeffect` (see `style.css`). Always `esc_html__('Label', 'mbeffect')` / `__('...', 'mbeffect')`.
- **Required plugins:** ACF Pro (all blocks and fields depend on it — the whole block loader is wrapped in `class_exists('ACF')`), Gravity Forms. Integrations with Yoast SEO, SearchWP, and WP Rocket exist and are guarded with function/class checks.
- **Custom post types** (`src/functions/custom-post-type.php`): `product`, `popup`.
- **ACF options pages** (`src/functions/theme-settings.php`): `mb-settings`, `basic-details`, `footer` (post_id `footer`), `header`, `notification`, `not_found`, `utilities` (post_id `utilities` — image settings, preconnect hints, block version). Page-scoped settings live in `src/functions/acf/page-settings/`.
- **Starter blocks** (`blocks/`): `background`, `blog`, `centered-content`, `contact`, `content-image`, `hero`.
- **WooCommerce:** full scaffolding exists (`woocommerce/` template overrides, `src/functions/woocommerce/`, `src/styles/components/woocommerce/`) but is **disabled by default**: the SCSS is commented out in `src/styles/components/_main.scss` and the PHP is excluded from the autoloader. To activate on a project, uncomment the `@use "./woocommerce/woocommerce"` line and wire up the functions — don't build on it without asking.
- Comments are fully disabled site-wide (`src/functions/randomness.php`).
- `changelog.md` documents theme versions — keep it updated for notable base-theme changes (the README links to it).

**When this theme is forked for a client project:** the fork's `CLAUDE.md` should update this Project Overview (client name, CPTs, options pages, image sizes, block list, WooCommerce state) and keep the rest — the loader contract, helpers, and conventions below are the shared machinery.

## Local Development Environment

This project runs in **Local (by Flywheel)**. When working with WordPress runtime tasks (WP-CLI, database queries, plugin/theme activation, cache flushing, log inspection), invoke the `/wordpress-local` skill so Claude has the correct project layout in mind.

### Key paths (from the Local site root)

Each Local site lives under `~/Local Sites/<site-name>/` and contains a theme with the **same name** as the site. Confirm the actual name from the working directory — never hardcode.

```
~/Local Sites/<site-name>/
├── local-site.json                              # generated by Local — used by dev-watch (BrowserSync domain)
├── app/
│   └── public/                                  # WordPress root (WP-CLI works here)
│       ├── wp-content/themes/<theme-name>/      # THIS THEME (current working directory)
│       ├── wp-config.php
│       └── ...
├── logs/
│   ├── nginx/
│   └── php/
│       └── error.log                            # PHP errors
└── conf/                                        # Local configuration
```

`local-site.json` is **created by Local itself at the site root** — never write it by hand. `webpack.config.ts` reads it via `../../../../../local-site.json`, and only when `NODE_ENV=dev-watch` (for the BrowserSync proxy domain). Regular `dev`/`build` runs don't need it.

### Running WP-CLI from inside the theme directory

Because the current working directory is the theme, not the project root, run WP-CLI in a subshell that switches to `app/public/`:

```bash
# From the theme directory
(cd ../../../../ && wp plugin list)
(cd ../../../../ && wp cache flush)
(cd ../../../../ && wp db query "SELECT * FROM wp_options LIMIT 5")
```

To inspect PHP errors:

```bash
tail -n 100 ../../../../logs/php/error.log
```

## Build, Assets & Tooling

Node **>= 24** (`.nvmrc`, `engines`). The npm scripts (see `package.json`) set `NODE_ENV` via `cross-env`:

- `npm run dev` → `NODE_ENV=dev` (development build, with watch)
- `npm run dev-watch` → `NODE_ENV=dev-watch` (adds BrowserSync via `local-site.json`)
- `npm run build` → `NODE_ENV=production` (minified, no source maps)
- `npm run screenshots` → block screenshot generator (see Screenshots Workflow)

In `webpack.config.ts`, both `dev` and `dev-watch` resolve to webpack `mode: "development"`; `production` resolves to `mode: "production"`. When invoking webpack directly (without the npm scripts), use one of these `NODE_ENV` values — `NODE_ENV=development` is **not** recognized by this config and will fall through to the production branch.

### Entries and outputs

| Entry | Sources | Output |
| --- | --- | --- |
| `main` | `src/scripts/files/*.ts` + `blocks/*/*.ts` + `components/*/*.ts` + `src/styles/main.scss` | `dist/main.js` + `dist/main.css` |
| `admin` | `src/styles/admin.scss` | `dist/admin.css` |
| `fancybox/fancybox` | `src/scripts/files/fancybox/*.ts` | `dist/fancybox/fancybox.js` |

**Everything is auto-discovered — never register new files manually:**

- A new `blocks/<name>/<name>.ts` or `components/<name>/<name>.ts` is glob-collected into the `main` bundle by webpack.
- A new `blocks/<name>/_<name>.scss` or `components/<name>/_<name>.scss` is glob-imported by `src/styles/main.scss` (`@use "../../blocks/**/*.scss"`) through a **custom glob importer defined inside `webpack.config.ts`** (modern Sass API — not an npm glob-importer package; don't add one).
- A new PHP file in `src/functions/` is auto-required by `src/functions/autoload.php` (Symfony Finder) — no `require` needed. Exceptions: `src/functions/woocommerce/` is excluded, and `theme-helpers.php` / `theme-support.php` are loaded first from `functions.php`. New classes in `src/classes/` **do** need a manual `require_once` in `functions.php`.

**ESLint and Stylelint run inside every webpack build** (`eslint-webpack-plugin`, `stylelint-webpack-plugin`) over all `.ts`/`.scss` in the repo — lint errors fail the build. Configs: `eslint.config.mjs` (TS recommended + custom rules, tabs allowed), `.stylelintrc.js` (`stylelint-config-standard-scss`, `max-nesting-depth: 8`, `@use` must come before dollar-variables).

**Never edit anything in `dist/`** — it's build output and gitignored.

### Asset loading (`src/functions/enqueueing.php`)

- `dist/main.css` + `dist/main.js` (deferred, footer) on the frontend; `dist/admin.css` in wp-admin; `dist/fancybox/fancybox.js` separately.
- **Font Awesome Kit CSS is enqueued straight from `node_modules/@awesome.me/kit-47e6dc046c/`** — node_modules must exist wherever the theme runs.
- Core jQuery is replaced by a local copy (`src/scripts/libs/jquery-min.js`); dashicons are dequeued for logged-out users; Gravity Forms' own stylesheets (`gform_basic`, `gform_theme`, ...) are deregistered — GF is styled entirely by the theme.
- Cache-busting uses `filemtime()` — no manual version bumps.
- WP Rocket runs in production; scripts that must not be delayed are listed in the `rocket_delay_js_exclusions` filter.
- In SCSS use the `assets()` function (`url("../assets/<file>")`); in PHP use the `assets('file.svg')` helper (returns the URI into `assets/`). Same name, different layers.

## How ACF Blocks Work (the loader contract)

The loader (`src/functions/acf/loader/theme-init.php`) wires everything. Understanding it is **required** before creating or editing a block.

### Block anatomy

```
blocks/block-name/
├── block.json          # REQUIRED — without it the block is not registered at all
├── config.php          # ACF field configuration: returns ['fields' => [...]] and nothing else
├── view.php            # Template rendering
├── _block-name.scss    # Block-specific styles (auto-globbed)
└── block-name.ts       # Block-specific JavaScript (optional, auto-globbed)
```

### block.json owns identity; config.php owns fields

```json
{
	"name": "acf/block-name",
	"title": "Blokknaam (Dutch, shown to editors)",
	"acf": { "mode": "edit" },
	"supports": { "anchor": true, "align": false, "mode": false }
}
```

A `block_type_metadata` filter force-sets `apiVersion: 3`, the MB icon, the category, the render callback, and `hideFieldsInSidebar: true` on every ACF block — never specify those per-block. Blocks appear in the editor under the "MB blokken" category. Only whitelisted block types are insertable: theme blocks plus the core blocks listed in `allowed_block_types()` in `theme-init.php` — **to allow a new core block, add it to that list**.

### config.php: keys and names are auto-generated

```php
<?php
defined('ABSPATH') || exit('Forbidden'); // Exit if accessed directly.

return [
	'fields' => [
		'title' => [
			'label' => esc_html__('Titel', 'mbeffect'),
			'type' => 'clone',
			'clone' => [
				'clone_titles_block_title',
			],
			'display' => 'seamless',
		],
		'images' => [
			'label' => esc_html__('Afbeeldingen', 'mbeffect'),
			'type' => 'repeater',
			'button_label' => esc_html__('Nieuwe afbeelding', 'mbeffect'),
			'sub_fields' => [
				[
					'key' => 'field_block-name_images_image', // sub-fields DO need explicit keys
					'label' => esc_html__('Afbeelding', 'mbeffect'),
					'name' => 'image',
					'type' => 'image',
					'return_format' => 'id',
					'mime_types' => 'svg, png, jpg, jpeg, webp',
				],
			],
		],
	],
];
```

Loader rules, in order:

1. Unless the block is `background` or `hero`, `get_general_settings()` is **prepended** to the fields: an accordion plus `spacing_top` / `spacing_bottom` selects (`none|small|medium|large|extra-large`, default `medium`).
2. Each **top-level** field gets `key = field_<blockname>_<arraykey>` and `name = <arraykey>` auto-generated. An explicit `key`/`name` in the field definition overrides the auto one. **Sub-fields (repeaters, groups, flexible content) are not touched — give them explicit keys**, conventionally `field_<blockname>_<parent>_<name>`.
3. `conditional_logic` must reference the **auto-generated key**, e.g. `'field' => 'field_blog_selection'`.
4. All fields are wrapped in one ACF group named `group_<blockname>_fields`, ACF field group key `field_group_<blockname>`.

### view.php: fields arrive as ready-made variables

The render callback does `extract((array) get_field('group_<block>_fields', $block['id']))` — every top-level field from config.php is already a variable in scope. Standard skeleton:

```php
<?php
defined('ABSPATH') || exit('Forbidden'); // Exit if accessed directly.

/**
 * (Block name) Block Template.
 */

$section = general_section($block, [
	'class' => ['section', 'block-name'],
]);

// Fields are auto-extracted; add safe defaults before use.
$images = $images ?? [];

if (empty($images)) return;

echo !is_admin() ? '[raw]' : '';
?>

<section <?php attr($section); ?>>
	<div class="columns-12 center">
		<!-- block markup -->
	</div>
</section>
<?= !is_admin() ? '[/raw]' : ''; ?>
```

- `general_section($block, $attr_array)` returns an **attribute array** (echo it with `attr()`): it appends `pad--top-<value>` / `pad--bottom-<value>` spacing classes from the block's general settings, the anchor `id`, alignment classes, and any custom `className`. The `pad--*` utility classes live in `src/styles/components/_classes.scss`.
- **Why `[raw]`:** `my_formatter()` in `src/functions/randomness.php` replaces `wpautop` on `the_content`; content between `[raw]...[/raw]` skips auto-paragraphing so block HTML isn't mangled. Only echo the markers on the frontend (`!is_admin()`), exactly as above.
- Inner content wrapper convention: `columns-6` … `columns-12` width classes plus `center` (see `src/styles/components/_grid.scss`).

## ACF Field Patterns

### Reusable clones (`src/functions/acf/clones/`)

Registered clone groups — reference by key with `'type' => 'clone'`:

- `clone_titles_block_title` → a `block_title` group with `suptitle`, `main_title`, `subtitle`, `type` (heading type). With `'display' => 'seamless'` under a field named `title`, view.php receives `$block_title` (array). Render it with `layout('title', ['title' => $block_title, 'block' => $block])`.
- `clone_buttons_buttons_group` → flexible `buttons_group` (primary/secondary/… button layouts). Render with the `BlockButtons` class.
- Also: image and footer-column clones (see `src/functions/acf/clones/` for exact keys).

### Flexible content: `get_flex_content(string $template_type)`

Returns a complete flexible-content field (name `content`) with layouts: `title`, `content` (wysiwyg), `fold_content`, `image`, `logos` (repeater), `accordions` (repeater), `form` (Gravity Forms select), `buttons_clone`. Render the result with `layout('content', ['content' => $content, ...])`, which delegates to the `FlexContent` class.

### Automatic behaviors to know about

- Any ACF select whose **name contains `form_id`** is auto-populated with all Gravity Forms via an `acf/load_field` filter (`theme-helpers.php`).
- Registered image sizes (`src/functions/post-thumbnails.php`, only when enabled in the `utilities` options page): `Author thumb` 60×60, `Blog detail` 610×500, `Hero 900` 1920×900, `Hero mobile` 740×250, `Post` 400×270 — all cropped. Use these names in `wp_get_attachment_image()`. Projects typically adjust this list — check the file, not this doc, when in doubt.
- ACF wysiwyg: a minimal `title` toolbar is registered (link, underline, forecolor) — use `'toolbar' => 'title'` for title-ish fields, plus `'delay' => true`.

### ACF config conventions

- Use associative arrays with square brackets; **a single space around `=>`** — do NOT pad/align values vertically.
- Always `esc_html__('Label', 'mbeffect')` for labels; labels in Dutch.
- Use true/false for boolean values, not strings or integers.
- Top-level fields need no manual `key`/`name` (auto-generated); sub-fields do.

## PHP Helper Reference

Helpers in `src/functions/theme-helpers.php` unless noted. These are the project vocabulary — reach for them before writing new plumbing.

| Helper | Contract |
| --- | --- |
| `component(string $name, array $args = [])` | Includes `components/<name>/<name>.php`; `$args` are `extract()`ed into its scope. Silently returns if missing. |
| `layout(string $name, array $args = [])` | Includes `layout/layout-<name>.php`. Available: `content`, `image`, `title`. |
| `attr(array $attrs)` / `get_attr(array $attrs)` (`attributes.php`) | Array → HTML attributes. Value rules: `true` → bare attribute; string → `key="value"`; array of strings → space-joined. **Numbers crash it** (`array_map('esc_attr', ...)` on a non-array) — always cast to `(string)`. Build as `$attr['class'][] = '...'`. |
| `general_section(array $block, array $section)` | Returns the section attribute array with spacing/anchor/alignment classes (see block skeleton). |
| `get_general_settings(...)` | The auto-prepended spacing fields. The `$spacing_top`/`$spacing_bottom` params are currently dead — defaults are hardcoded `medium`. |
| `get_flex_content(string $template_type)` | Flexible content config (see above). |
| `assets(string $file)` | URI into the theme's `assets/` folder. |
| `get_logo(array $args = [])` | Home-linked logo `<a>` from the `logo` option (or `$args['name']` for alternates). |
| `calculate_title_element($block)` | 1 if the block is the first on the page (→ `h1`), else 2. Used by `layout-title`. |
| `get_all_forms()` | `[form_id => title]` for Gravity Forms selects. |
| `notification()` (`notification.php`) | Renders the global notification bar from the `notification` options page, with from/until scheduling. |
| `wpex_pagination()` (`pagination.php`) | Main-query pagination (`pagina/%#%/` permalinks). |
| `wpex_pagination_outside_query($total, $anchor = '')` | Pagination for custom queries via the `?pagina=` GET param; outputs `.page-number-wrapper` markup styled in `src/styles/components/blog/_pagination.scss`. |
| `sanitize_title_custom($title)` (`randomness.php`) | strip_tags allowing `i, em, b, strong, u, a, br, span` — run on wysiwyg titles before output. |
| `get_review_stars($score)` (`randomness.php`) | 1–10 score → accessible star markup (`role="img"` + `aria-label`). |
| `reading_time($post_ID)` (`randomness.php`) | "X min" reading time across ACF block content. |

**Classes** (`src/classes/`, required manually in `functions.php`): `BlockButton`/`BlockButtons` (button.php), `FlexContent`, `BlockTitle` (title.php), popup class, two nav-menu walkers.

### Comment Guidelines

#### When to Comment

**ALWAYS comment:**

- Complex business logic or algorithms
- WordPress hooks and filters
- Security-related code
- Performance optimizations
- Browser-specific workarounds
- ACF field relationships and dependencies
- Database queries and data manipulation
- Third-party integrations (Gravity Forms, WooCommerce)

**DON'T comment:**

- Self-explanatory code
- Simple variable assignments
- Standard WordPress functions
- Basic HTML structure

#### Comment Style Guidelines

1. **Use clear, concise language**
2. **Write comments before writing code** (helps clarify thinking)
3. **Update comments when code changes**
4. **Use proper grammar and spelling**
5. **Avoid obvious comments** (`$i++; // Increment i`)
6. **Explain WHY, not WHAT**

#### Comments to Ignore

**DO NOT flag or comment on these common patterns:**

- **Black/white color values** - Variables like `#000;` or `$color-white: #fff;` are self-explanatory
- **Fixed pixel values** - Values like `height: 80px;` or `border-radius: 4px;` don't need explanation / variables
- **Magic numbers with clear context** - Numbers used in well-named variables or clear mathematical operations (e.g., `$grid-columns: 12;`, `width: 100% / 3;`)
- **Loading fields** - ACF fields are loaded automatically and are extracted within the view.php files
- **ACF keys** - Top-level fields in `config.php` do not require manual keys as they are automatically generated.

#### Special Comment Types

```php
// TODO: Implement caching for product queries
// FIXME: Mobile layout breaks on Safari iOS 14
// HACK: Temporary workaround for ACF bug #1234
// NOTE: This function depends on session being started
// WARNING: Do not modify without updating related CSS
```

## Coding Standards & Conventions

### PHP Coding Standards

#### Array Syntax

- **ALWAYS use square bracket syntax `[]` for arrays, NEVER `array()`**
- **Use a single space around `=>`** — do NOT pad/align values vertically.

```php
// Correct
$fields = [
    'key' => 'value',
    'items' => [
        'item1',
        'item2'
    ]
];

// Incorrect — do not align with extra spaces
$fields = [
    'key'   => 'value',
    'items' => [...],
];
```

#### WordPress Patterns

- Use `defined('ABSPATH') || exit('Forbidden');` at the top of PHP files
- Use consistent prefixes for ACF field keys (`field_`, `clone_`, `theme_settings_`)
- Sanitize all `$_GET`/`$_POST` input (`sanitize_text_field`, `absint`); escape all output (`esc_html`, `esc_attr`, `esc_url`)
- Use PHP short echo tags — `<?= $variable ?>` — for outputting variables in templates

### CSS/SCSS Standards

#### BEM Methodology

**STRICTLY follow BEM (Block Element Modifier) naming convention:**

```scss
// Block
.hero {
}

// Element (use double underscore)
.hero__title {
}
.hero__content {
}

// Modifier (use double dash)
.hero--large {
}
.hero__title--centered {
}
```

#### SCSS Organization

- Every partial starts with `@use "abstracts" as *;` (which forwards `partials/config`, `partials/functions`, `partials/variables`, `partials/mixins`). Placeholders come from `@use "placeholders" as *;`.
- Use partial files with underscore prefix `_filename.scss`.
- `src/styles/main.scss` imports fonts → normalize → `components/_main.scss` (general, content-layout, classes, titles, head, forms, grid, footer, blog, search, 404, tooltip, fold-content, sitemap, review-stars, buttons, color-palette, fancybox, swiper) → auto-globbed block and component partials. Shared/theme-wide styles belong in `src/styles/components/`; block- or component-specific styles stay next to their block/component.
- Nest with `&__element` / `&--modifier`; Stylelint enforces `@use` first, then dollar-variables, then declarations, then nested rules (max depth 8).

```scss
@use "abstracts" as *;

.block {
	&__element {
		&--modifier {
			// styles here
		}
	}
}
```

#### Functions and Variables (`src/styles/partials/`)

- `pxtorem($px)` — px → rem, **fixed base 16** (browser default).
- `pxtoem($px, $base: 18)` — px → em against `$base-font-size: 18` (the body size). Don't mix the two up.
- Color variables (`_variables.scss`): `$text-color`, `$hue-accent-1`, `$hue-dark-1..3`, `$hue-light-1..4`, `$btn-primary`, `$form-error`. Projects re-tint these on fork — always use the variables, never raw brand hex values.
- Spacing variables: `$pad-mobile-small`/`$pad-small` … `$pad-mobile-extra-large`/`$pad-extra-large` — these power the `pad--top-*`/`pad--bottom-*` classes; don't hardcode section spacing.
- Fonts (`_config.scss`): the site font stack, plus `$fa` (Font Awesome 6 Pro), `$fab` (Brands), `$fak` (**Font Awesome Kit** — custom icons).
- Use the `assets()` function for asset paths.

#### Font Awesome Icons

**Render icons with CSS pseudo-elements, NOT `<i class="fa-...">` elements.** This is the established theme pattern (see `.review-stars` in `_review-stars.scss`).

- Icon glyphs are centralized as unicode codepoints in `src/styles/partials/_variables.scss` (e.g. `$fa-arrow-right: "\f061";`). Add new icons there.
- Apply an icon on a `::before`/`::after` with `content: $fa-name;` plus the right family and weight — **weight selects the style**: `900` = solid, `400` = regular/brands, `300` = light.
- **Custom kit icons** use `font-family: $fak;` with `font-weight: 400;`. The kit ships via the npm package `@awesome.me/kit-47e6dc046c` and its CSS is enqueued from node_modules.

```scss
.block__icon::before {
	content: $fa-arrow-right;
	font-family: $fa;
	font-weight: 900;
}
```

**Why:** class-names change between FA major versions (`fa` → `fas` → `fa-solid`), which would break markup across many templates; unicode codepoints are stable and live in one file.

**Accessibility:** pseudo-element glyphs are ignored by screen readers, so:

- **Decorative** icons need nothing extra (no stray `<i aria-hidden>`).
- **Meaningful/interactive** icons (icon-only link/button, ratings) MUST carry a text alternative on the element itself — `aria-label` on the link/button, or `role="img"` + `aria-label` on the wrapper (see `get_review_stars()` in `src/functions/randomness.php`). Never rely on the icon alone to convey meaning.

### TypeScript/JavaScript Standards

- Use strict TypeScript with proper type annotations; query DOM elements with specific types:

```typescript
const buttons = document.querySelectorAll<HTMLButtonElement>(".button");
const input = document.querySelector<HTMLInputElement>("#input");
```

- Use `addEventListener` for all event binding, arrow functions for callbacks, `forEach` for NodeList iteration:

```typescript
buttons.forEach((button) =>
	button.addEventListener("click", () => {
		// handler logic
	}),
);
```

- Import external libraries at the top; use ES6 imports/exports.
- Shared site scripts live in `src/scripts/files/` (accordion, fold-content, menu-toggle, notification, slide-toggle, …); block/component scripts live next to their block/component. All are auto-bundled — a new `.ts` file in those folders just works.
- ESLint: TS-recommended rules, tabs, `wrap-iife` enforced; `window`, `document`, `wp` are the only assumed globals.

```php
if (!empty($news_items)) {
    foreach ($news_items as $item) {
        component('post', [
            'title' => $item['title'],
            'image' => $item['image'],
            'link' => $item['link']
        ]);
    }
}
```

## Layout, Popup & Button Systems

### Layout System (`layout/`)

- `layout('title', ['title' => $block_title, 'block' => $block, 'centered' => false])` — renders the title-clone group through `BlockTitle`; heading level is `h1` for the first block on the page, `h2` otherwise (`calculate_title_element()`), unless the editor picked an explicit type. Titles pass through `sanitize_title_custom()`.
- `layout('content', ['content' => $content, ...])` — walks a `get_flex_content()` value and renders each layout row via the `FlexContent` class (chainable `setContent`, `setImage`, `setLogos` (optional Swiper), accordions, forms, buttons).
- `layout('image', [...])` — image rendering with focal-point support (`src/functions/focalpoint.php`).

### Popup System

- `popup` CPT + `components/popup/` + `src/classes/popup.php` + `src/functions/popups.php`; ACF settings under `src/functions/acf/page-settings/popups.php`. Popups can also be placed via the `[popup id="popup-name"]` shortcode; global popups are queued and rendered in the footer.
- Markup contract: `<div class="popup" data-popup="<id>">` with `.popup__close`; open triggers carry `.show-popup` and a matching `data-popup`.
- TS: `openPopup(popupName)` / `closePopup()` handle staggered `popup--active`/`popup--show` classes, a `no-scroll` body lock, and iframe reset on close.

### Button System

- **PHP:** `BlockButton` (single) and `BlockButtons` (renders a `buttons_group` clone value). Buttons render as `<a>`/`<button class="btn btn--primary">` containing `$icon_before . '<span>' . $text . '</span>' . $icon_after`.
- **SCSS:** `src/styles/_placeholders.scss` defines the `%btn` placeholder family; `_buttons.scss` maps them to `.btn--*` classes. The pattern: the `<a>`/`<button>` is a flex container, the **`<span>` is the pill**, and any circular icon renders on the element's own pseudo-element so the icon is part of the clickable element. Reuse via `@extend %btn--primary;` — don't rebuild pills by hand.
- **Gravity Forms:** `input_to_button()` in `src/functions/gravity-forms.php` converts GF submit/next/prev `<input>`s to `<button><span>label</span></button>` so the same button styling applies.
- Display control fields: `phone` / `desktop` / empty (all devices); action is either a link or a popup trigger.

## Screenshots Workflow (PR visuals)

`npm run screenshots` (Playwright, `src/scripts/files/screenshots/`) detects blocks changed vs. the base branch via git, asks the live Local site which pages use them (REST endpoints in `src/functions/screenshots-api.php`, authenticated via the auto-generated `.screenshots-token` — gitignored), and captures per-breakpoint screenshots into `playwright/screenshots/`. Flags: `--block=<name>`, `--page=<url>`, `--detect-only`.

- Screenshots are **committed** on the feature branch; the `playwright.yml` workflow comments them on the PR when view/scss files changed; `cleanup-screenshots.yml` wipes them from `development` after merge.
- Run it after visual changes to blocks/components so the PR carries proof.

## Definition of Done

Work is finished only when all of these hold — run the checks, don't assume:

1. **PHP:** `php -l <file>` passes on every touched PHP file, and `tail -n 50 ../../../../logs/php/error.log` shows no new notices/warnings from the change (load a relevant page first).
2. **Build:** SCSS/TS changes compile — `npm run dev` (or the running `dev-watch`) completes with **zero ESLint/Stylelint errors**. Changes are invisible on the site until compiled. Ask before running a build if a watcher may already be running.
3. **New files** land in auto-discovered locations (block/component folders, `src/functions/`) — no manual imports, no edits in `dist/`.
4. **Blocks/fields:** verify in both the editor (fields appear, mode `edit` works) and the frontend (markup, spacing classes, `[raw]` guards). Field-key changes need an editor reload.
5. **Design:** when a Figma design is referenced, match it px-for-px at the design's breakpoint and keep it sane at the others (mobile-first).
6. **Visuals:** for visible block/component changes, offer to run `npm run screenshots` for the PR.
7. **Conventions:** BEM classes, Dutch labels with `'mbeffect'`, `[]` arrays, tabs, helpers used where they exist.
8. Commit only when asked; use the commit format below.

- **Base branch for PRs: `development`.** `master` only accepts PRs from `development` or `hotfix/*` (enforced by `master.yml`).

## Common Pitfalls to Avoid

1. **Use modern PHP syntax** - Always use `[]` for arrays, never `array()`
2. **Don't mix BEM naming** - Stick to `block__element--modifier`
3. **Avoid deep nesting** - Keep SCSS nesting reasonable (Stylelint caps at 8)
4. **Don't forget type annotations** - Use proper TypeScript types
5. **Always check for elements** - Use optional chaining or null checks; default extracted PHP variables
6. **Follow WordPress security** - Sanitize inputs, escape outputs, use nonces
7. **Don't hardcode values** - Use variables, helpers, and the spacing system
8. **Test on mobile** - Mobile-first development approach
9. **Avoid inline styles** - Use classes and SCSS for styling
10. **Use PHP short echo tags** - `<?= $variable ?>` for outputting variables
11. **Never pass numbers to `attr()`** - cast to `(string)` or it throws a TypeError
12. **A block without `block.json` doesn't exist** - the loader skips it entirely
13. **`conditional_logic` needs the auto key** - `field_<block>_<fieldname>`, not the plain field name
14. **Never edit `dist/`** or add glob-importer npm packages - the build owns both
15. **`[raw]` markers only on the frontend** - always behind `!is_admin()`
